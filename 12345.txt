Чтобы сборка в Vite проходила корректно, важно правильно настроить файл vite.config.js. 
Я подобрала ключевые моменты, на которые стоит обратить внимание.
Базовая структура конфига
Начните с шаблона:
import { defineConfig } from 'vite';

export default defineConfig({
  plugins:, // Здесь будут подключаться плагины
  build: {
    // Настройки сборки
  },
});
``` 

**Функция `defineConfig`** — это хелпер для статической типизации. Он не меняет конфигурацию, 
но даёт подсказки в IDE, что упрощает работу. 
[4](https://purpleschool.ru/knowledge-base/react/project-launch/vite-react)

## Что важно настроить

*   **Плагины.** Добавьте плагины, которые нужны вашему фреймворку или библиотеке. Например, для Vue:
    ```javascript
    import vue from '@vitejs/plugin-vue';
    ```
    Также могут понадобиться плагины для React, Svelte и другие. 
    [7](https://laravel-docs.com/ru/docs/10.x/vite)[3](https://laravel.su/docs/13.x/vite)

*   **Опция `build`.** Внутри объекта `build` задаются настройки, которые влияют именно на сборку (в отличие от режима разработки). [2](https://vite-docs.ru/guide/build)[4](https://purpleschool.ru/knowledge-base/react/project-launch/vite-react)
    *   **`outDir`**: Директория, куда будут помещены собранные файлы (по умолчанию `'dist'`). [10](https://tr-page.yandex.ru/translate?lang=en-ru&url=https%3A%2F%2Fgithub.com%2Fvitejs%2Fvite%2Fblob%2Fmain%2Fdocs%2Fconfig%2Fbuild-options.md)[4](https://purpleschool.ru/knowledge-base/react/project-launch/vite-react)
    *   **`sourcemap`**: включать ли исходные карты (полезно для отладки, но может увеличивать размер бандла). [4](https://purpleschool.ru/knowledge-base/react/project-launch/vite-react)
    *   **`rollupOptions`**: глубокая настройка Rollup (используется внутри Vite). [2](https://vite-docs.ru/guide/build)[4](https://purpleschool.ru/knowledge-base/react/project-launch/vite-react)
    *   **`cssCodeSplit`**: разделять ли CSS на чанки. [10](https://tr-page.yandex.ru/translate?lang=en-ru&url=https%3A%2F%2Fgithub.com%2Fvitejs%2Fvite%2Fblob%2Fmain%2Fdocs%2Fconfig%2Fbuild-options.md)[12](https://vite.dev/config/build-options)
    *   **`cssMinify`**: минифицировать ли CSS. [10](https://tr-page.yandex.ru/translate?lang=en-ru&url=https%3A%2F%2Fgithub.com%2Fvitejs%2Fvite%2Fblob%2Fmain%2Fdocs%2Fconfig%2Fbuild-options.md)[12](https://vite.dev/config/build-options)
    *   **`target`**: целевая версия браузеров для бандла. [12](https://vite.dev/config/build-options)
    *   **`emptyOutDir`**: очищать выходную директорию перед сборкой. [1](https://habr.com/ru/companies/croc/articles/816803/)[4](https://purpleschool.ru/knowledge-base/react/project-launch/vite-react)

*   **Точка входа.** По умолчанию Vite использует `index.html` в качестве точки входа. Если у вас несколько HTML-файлов (многостраничное приложение), их нужно явно указать в `build.rolldownOptions.input`. [2](https://vite-docs.ru/guide/build)[8](https://vite.dev/guide/build)

*   **Разрешение путей (`resolve`).** Если вы используете алиасы (например, `@` для папки `src`), настройте их здесь.
    ```javascript
    resolve: {
      alias: {
        '@': fileURLToPath(new URL('./src', import.meta.url)),
      },
    },
    ``` [11](https://purpleschool.ru/knowledge-base/vue/tools/vite)

*   **Базовый путь (`base`).** Если приложение будет развёрнуто не в корне домена (например, по пути `/app/`), задайте `base` в конфигурации.
*   **Переменные окружения.** Vite поддерживает файлы `.env.*`. Переменные, которые должны быть доступны в клиентском коде, должны начинаться с `VITE_`.

 [11](https://purpleschool.ru/knowledge-base/vue/tools/vite)

## Пример итоговой конфигурации

```javascript
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({
  plugins: [vue()],
  build: {
    outDir: 'dist',
    sourcemap: false,
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['vue', 'vue-router', 'pinia'],
        },
      },
    },
    cssCodeSplit: true,
    cssMinify: true,
    target: 'es2015',
    emptyOutDir: true,
  },
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
  base: '/app/',
});

Содержимое ответа
Чтобы в Vite (с React) удобно и правильно настроить пути импорта, нужно поработать 
с опцией resolve.alias в файле vite.config.js. Я подобрала основные сценарии 
— выбирайте под свою структуру проекта.
1. Базовый алиас (самый частый случай)
Этот способ позволяет писать импорты без указания src/ в начале пути. 
Например, import Button from '@/components/Button' вместо 
import Button from '../../components/Button'. 
stackoverflow.com
dev.to
// vite.config.js
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import path from 'path';

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src'), // Теперь '@' означает корень src
    },
  },
});
Важное замечание: в реальных проектах замените ./src на реальное имя вашей корневой папки 
(например, ./app или ./assets). Иначе алиас не сработает. 
stackoverflow.com
2. Несколько алиасов для разных папок
Можно задать несколько отображений.
resolve: {
  alias: {
    '@components': '/src/components',
    '@utils': '/src/utils',
    '@pages': '/src/pages',
  },
},
Теперь в коде можно писать:
import Header from '@/components/Header';
import Home from '@/pages/Home';
3. Алиасы через массив (гибкий синтаксис)
Иногда удобнее использовать массив объектов с find и replacement.
resolve: {
  alias: [
    { find: '@components', replacement: '/src/components' },
    { find: '@utils', replacement: '/src/utils' },
  ],
},
4. Интеграция с jsconfig.json
Чтобы IDE (например, VS Code) корректно подсказывала типы и работала навигация по алиасам, 
полезно добавить конфигурацию в jsconfig.json в корне проекта. 
geeksforgeeks.org
dev.to
// jsconfig.json
{
  "compilerOptions": {
    "baseUrl": "./",
    "paths": {
      "@components/*": ["src/components/*"],
      "@utils/*": ["src/utils/*"]
    }
  }
}
Важный нюанс: чтобы Vite «слушался» jsconfig.json и использовал указанные алиасы, 
в конфигурацию vite.config.js нужно добавить плагин vite-jsconfig-paths. 
dev.to
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import jsconfigPaths from 'vite-jsconfig-paths'; // Добавьте этот импорт

export default defineConfig({
  plugins: [react(), jsconfigPaths()],
});
Несколько советов
Не смешивайте подходы. Если вы используете алиас через resolve.alias, не пытайтесь дополнительно настраивать paths в tsconfig.json — это избыточно. 
geeksforgeeks.org
Перезапускайте сервер. После любых изменений в vite.config.js (особенно если добавляли плагины вроде vite-jsconfig-paths) обязательно перезапустите сервер разработки (npm run dev или yarn dev). 
dev-notes.ru
Проверяйте ошибки. Если импорт всё равно не разрешается, проверьте, действительно ли файл существует по указанному пути. 
stackoverflow.com
